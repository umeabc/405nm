# 从彩翻（moeflow）迁移到 405nm

把旧站的用户、团队、作品、图片、标号、译文、署名台账搬进新站。工具的设计目标只有一条：
**跑完之后，能拿出一份证明「没丢东西」的报告**，而不是「跑完了，应该没问题」。

```
deploy/moeflow-export.sh                      ← 只读导出旧库快照（EJSON）
backend/src/cli/migrate-moeflow.ts            ← 盘点 / 迁移 / 核验
backend/src/migrate/                          ← 计划、映射规则、写库步骤、核验
```

## 一、命令

```bash
# 1) 只读导出（在能访问旧 mongo 容器的机器上；脚本里没有账号密码，凭据在容器内展开）
./deploy/moeflow-export.sh /opt/405nm/rehearsal/export [mongo 容器名]

# 2) 盘点：只算不写。先看它，确认清单与有损点
node backend/dist/cli/migrate-moeflow.js inventory --export <导出目录>

# 3) 迁移：写库 + 就地核验。可中断重跑，重复执行不会写重复行
node backend/dist/cli/migrate-moeflow.js migrate --export <导出目录> \
  --images-dir /path/to/old-storage          # 或 --images-base-url <网址前缀>

# 4) 只核验（不写任何东西）
node backend/dist/cli/migrate-moeflow.js verify --export <导出目录>
```

`--report <文件>` 指定报告路径，默认写在导出目录下的 `migrate-report.json`。
**退出码**：报告里有硬性对账失败 → 1，否则 0。

在测试机上跑（容器里已有全部依赖）：

```bash
cd /opt/405nm
docker compose -f deploy/docker-compose.yml run --rm \
  -e DATABASE_URL="postgres://nm405:<口令>@db:5432/nm405_rehearsal" \
  -e STORAGE_DIR=/data/uploads/rehearsal \
  backend node backend/dist/cli/migrate-moeflow.js migrate --export /rehearsal/export --images-base-url <旧站图源前缀>
```

> 演练务必指向**另一个数据库**（如 `nm405_rehearsal`）与**另一个存储子目录**，
> 这样既不动真库，也不会把演练的图混进真图库。

## 二、为什么它能重跑

每个对象的新 ID 都是 **`uuidv5('moeflow:<集合>:<ObjectId>')`** —— 由旧文档算出来的确定性 ID。
于是：

- 「这一条迁过没有」不需要映射表，重新算一遍 ID 就知道了；
- 中断后重跑，已存在的行不会被重复插入，缺的行会被补上（写库统一 `onConflictDoNothing`）；
- 图片字节按同样的键派生，重跑**不会**把几万张图重下一遍
  （已存在且 `size > 0` 的行直接跳过；上次因缺字节落成空行的会重试）。

**只增不改**：被人工改脏的行不会被自动改回去（那等于用迁移覆盖运维操作）。
核验会把它们报出来，由人决定是删行重迁还是手工修。

## 三、无损的边界

「无损」指的是**领域数据 + 图片 + 署名台账**。以下**刻意不迁**，报告里各有明确去向：

| 不迁的东西 | 理由 |
|---|---|
| 第三方凭据（Cookie / session / app password / R2 密钥） | 运维态而非历史数据；一律不进新库，在新站加密重新录入 |
| 术语库（tip / term_bank / term_group / term） | 新站暂无术语库（M8 才落地） |
| 站内信 / 申请 / 邀请（message / application / invitation） | 新站改用邀请码，没有对应的收件箱 |
| 站点设置（site_setting） | 内含凭据；其余项在新站后台重设 |
| 操作日志 / 错误日志 / 任务运行态 | 随导出快照归档，不进新库 |
| 各类计数器（sc / tsc / csc 等） | 原值本就漂移，照搬会污染新库，改为按需聚合 |
| 文件安全检测、解析进度、OCR 进度 | 新站没有这些功能 |

有损点（**迁了，但形态变了**）逐类记进报告，见下一节。凡是需要业务判断的，
`confirm` 为 true，报告结论会停在 `PASS_WITH_CONFIRMATIONS`，等人看一眼才放行。

## 四、报告怎么读

`migrate-report.json` 四块，缺一不可：

- **checks**：硬性对账。`fail` 即整体失败（退出码 1）。包含逐表逐字段比对的结果、
  图片字节摘要复算、行数复查、导出快照自检。
- **lossy**：有损点，逐类计数 + 样例 id。`confirm` 的条目要人确认。
- **dispositions**：旧库**每一个集合**的去向。认不出的集合直接判失败 ——
  不允许「旧站多了个新集合，而迁移悄悄没管」。
- **counts**：每张表的「源有多少 / 本次写了多少 / 已存在多少」。

核验的口径值得强调：**它拿同一份计划重算一遍期望值，再与库里的行逐字段比**。
不是「迁移时记下写了什么、之后再自己跟自己比」—— 那种只能证明「写进去的等于它想写的」。

## 五、迁移做了哪些形态转换

这些是**看代码不容易一眼看出来**、但会直接影响数据形态的地方：

- **角色按组复制**：旧站的系统角色是**全局一份**，本站是**每个团队/作品一套**。
  迁移时给每个组复制一份系统角色（等级与权限照旧，权限只做「只增」补齐），
  自定义角色一对一迁；成员关系按「组 + 旧角色」重新指向本组的那份。
  另外**每个团队还要补一套项目角色模板**，否则旧团队新建作品时无角色可用。
- **标号是点不是框**：旧站只有中心点 + 可选多边形，本站的 `w/h` 由多边形包围盒合成；
  没有多边形的记 0（是「没有框」，不是「框在左上角」）。多边形原样留在 `vertices` 里。
- **译文任何人都可能没选**：旧站允许一份都不选（导出时另按一套顺序兜底）。
  本站的导出与进度只认「选中」，所以迁移时按旧站的挑法（选定 → 校对稿非空 → 编辑时间）
  **把最佳的那一份落成选中**，否则那些译文在新站等于不存在。
- **署名台账的顺序即显示顺序**：按旧站 token 的先后逐行插入，`seq` 严格递增。
  这一条错了，界面上显示出来的署名会静默变序 —— 所以核验里有专门一条按序比对。
- **文件状态是推定的**：旧站没有状态机。迁移按译校进度推一个状态
  （口径比本站的流转前置条件更严，所以推出来的状态一定满足新站的前提），并写一条状态流水。

## 六、演练（正式切换前必做）

1. 导出快照到一个**新的**宿主目录。
2. 在新库里建一个**独立的数据库**，跑一次 `drizzle-kit migrate`（或镜像里的 `db/migrate.js`）。
3. `inventory` → 逐条看有损点，确认每条都能接受（不接受的先改映射规则，别硬跑）。
4. `migrate` → 看报告：`checks` 全 ok、`counts` 的「源」与旧库计数一致。
5. **再跑一次 `migrate`**：`counts` 里本次写入应当全是 0（幂等），且核验仍然通过。
6. `verify` 单独再跑一次：确认核验与迁移是两件独立的事。
7. 抽查界面：登录（含旧密码）、作品列表、翻校工作台里的标号位置、导出 txt。

## 七、排障

| 现象 | 含义 |
|---|---|
| `translation.json 的 o 不是升序` | 导出没带 `--sort '{o:1,t:1}'`。**不要绕过**：顺序不对会让译文配错标号 |
| `source.json 不是按 _id 升序` | 同上，`--sort '{_id:1}'` |
| `export-count:<集合>` 失败 | 文件行数与 manifest 不符 —— 导出被截断，重新导 |
| `export-collections` 失败 | 出现了没登记去向的集合：先确认它是旧站新功能还是漏登记 |
| `invite-code-conflict` 失败 | 旧邀请码与站内已有码撞了。先改掉其中一个（不自动改，因为码是要念给人的） |
| `file-bytes-missing` 有值 | 旧存储里找不到图。检查图源配置（目录挂错 / 地址前缀不对），修好后重跑会重试 |
| 核验报「缺行」 | 上次迁移被中断。重跑 `migrate` 即可补上 |
| 核验报「字段不符」 | 行被人工改过。迁移不会覆盖，需人工决定 |

## 八、安全

- 导出与迁移**全程只读旧站**：只发查询、只读存储；不在旧容器里写文件。
- 报告里**不出现**图片源地址（可能含内网 IP / 站点域名），只写来源类型。
- 旧凭据一律不迁，也不进报告。
- 图源地址这类内网信息只作为命令参数在演练时传入，**不进仓库**。
